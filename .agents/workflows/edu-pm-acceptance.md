# PM功能验收清单工作流

本工作流旨在帮助产品经理在研发提测后或上线前，快速生成结构化的自测清单，确保核心业务流程走通、异常分支被处理、UI高保真还原。

## 适用场景
- 研发提测后的 PM 走查（Sanity Check）
- 上线前的产品功能验收
- 视觉/交互还原度核对

## 需求目录与档案（落盘前必读）
先确定产品项目根目录，读取 `.agents/references/requirement-record.md`，按 `requirement_id` 找到现有档案。首次落盘时可运行 `python3 scripts/pm_requirement.py --project <产品项目根> --name <需求名>`。档案父目录称 `REQ_DIR`；清单存入 `REQ_DIR/验收清单/`。项目可用 `pm-forge.json` 配置项目内 `artifact_root`；下文 `{需求名称}/` 均指 `REQ_DIR`。

## 执行步骤

### Step 1: 读取 PRD 源文件
1. 优先读取档案 `artifacts.prd` 指向的 PRD；没有登记时在 `REQ_DIR/需求文档/` 查找，并补记路径。用户也可指定其他 PRD。
2. 完整读取 HTML 和档案中的 `requirements[]`、`metrics[]`。
3. 提取功能模块、`data-requirement-id`、业务规则、各行边界说明与数据埋点；没有 PRD 时依据用户给定范围建清单，在档案记下缺失来源。

### Step 2: 拆解验收维度
将提取的内容转化为可执行的 Check-list。每项分配稳定 `A-*` ID，关联 `R-*` 需求项；无法对应的项目标为待确认。分类如下：
1. **核心流程**：主线路径是否畅通（如：进入入口 -> 填写内容 -> 提交成功 -> 状态更新 -> 查看结果）。优先级 P0。
2. **边界与异常**：网络断开、超时、无权限、次数用尽、不合规输入等边缘场景的处理。优先级 P0/P1。
3. **UI 还原度**：关键页面的布局、颜色、交互动效、加载状态是否与需求/原型一致。优先级 P1/P2。
4. **数据埋点**：核心转化漏斗的埋点是否触发（如果有条件验收）。

### Step 3: 生成《功能验收清单》HTML
1. 产物按需求名分文件夹：在 `{需求名称}/验收清单/` 子目录中创建 HTML（该需求顶层目录不存在则先创建）。
2. 文件命名规范：`{需求名称}/验收清单/{需求名称}-验收清单.html`。
3. **UI 与交互规范**：
   - 使用现代化、清爽的界面风格（浅色为主，类似 Notion/Linear）。
   - **三态选择器**：每个验收项通过点击在“✅ 通过”、“❌ 未通过”、“⏭️ 跳过”之间切换。
   - **进度统计**：顶部悬浮展示通过率进度条，以及各状态的数量统计。
   - **过滤功能**：支持按状态筛选列表（全部、待验收、通过、未通过）。
   - **模块折叠**：支持按一级模块折叠/展开验收项。
   - **本地存储**：可用 `localStorage` 保存浏览器草稿，页面上明确显示“本地草稿”。
   - **可携带结果**：导出包含 `requirement_id`、各 `A-*` ID、状态、检查时间和证据链接的 `验收结果.json`；导入同一 JSON 可恢复进度。浏览器草稿不能代替正式结果文件。
4. 将清单路径写入档案 `artifacts.acceptance`。收到正式验收结果后，同步更新档案 `acceptance[]`；失败项附证据与后续处理，不能仅凭清单文件存在就标为通过。

## 输出交付物
- 可交互的功能验收清单 (`{需求名称}/验收清单/{需求名称}-验收清单.html`)
- 正式验收结果 (`{需求名称}/验收清单/验收结果.json`，验收执行后生成)
